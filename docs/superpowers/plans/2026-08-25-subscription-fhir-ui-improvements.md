# Subscription/SubscriptionStatus/SubscriptionTopic UI Improvements Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fill display/navigation gaps on the Subscription, SubscriptionStatus, and SubscriptionTopic resource pages; add cross-links to/from Person and Patient; fix date-column sorting and the 100-row cap in the spreadsheet viewer.

**Architecture:** This app's `src/pages/resources/*.tsx` files are 100% generated (never hand-edited) by `src/generator/generate_components.py`, which renders `template.javascript.component.jinja2` once per FHIR resource type using two config files: `partials_mapping_for_fields.py` (maps a backbone-element *type name* to a hand-written partial component under `src/partials/`) and `reverse_references.py` (maps a resource type to a list of "related resources" links rendered via the existing `ReverseReference`/`ReverseReferenceLink` components). Most tasks below therefore: (a) write a new hand-authored partial component, (b) register it in one of those config files (or, for resource+field-specific one-off fields, add a bespoke `{% elif fhir_entity.cleaned_name == "X" %}` branch to the shared Jinja2 template — the same pattern already used for `Organization.name` and `DocumentReference.description`), then (c) regenerate via `make generate_components` and verify only the intended files changed. `SpreadsheetViewer.tsx` (tasks 9–10) is hand-written and untouched by the generator.

**Tech Stack:** React 19 + TypeScript, MUI, react-router, ag-grid-react (`SpreadsheetViewer`), Vitest + React Testing Library for unit tests, Python 3.8 + Jinja2 (via Docker, `make generate_components`) for the page generator.

**Spec:** This plan file — no separate spec doc. Requirements came directly from conversation with the repo owner (Imran), refined via one clarifying round-trip on the "Subscription → Patient link" design (see Task 5).

## Global Constraints

- Never hand-edit any file under `src/pages/resources/` — it is wiped and fully regenerated by `make generate_components`. All durable changes go into `src/generator/*.py`, `src/generator/template.javascript.component.jinja2`, or new files under `src/partials/`.
- After any generator-config/template change, run `make generate_components` (requires Docker; installs `lxml`+`jinja2` into a throwaway `python:3.8-slim-buster` container) and then `git status`/`git diff --stat -- src/pages/resources` to confirm only the intended resource page(s) changed — the whole folder is rewritten every run, so a stray edit in the shared template could silently touch all ~150 resource pages.
- This codebase does not unit-test generated resource pages or simple display-only partials today (confirmed: `Subscription.tsx`, `SubscriptionStatus.tsx`, `Reference.tsx`, `ReverseReference.tsx`, `Meta.tsx`, etc. have no tests). Match that convention: only add unit tests for genuinely new non-trivial logic (duration math, column-type inference, sort-by-eventNumber), not for straightforward table-rendering partials.
- Explicitly out of scope for this plan: `SubscriptionTopic.contact` (`TContactDetail[]`) and `SubscriptionTopic.useContext` (`TUsageContext[]`). Neither partial exists anywhere in the codebase yet, and both fields belong to FHIR's shared `MetadataResource` pattern used by ~15+ other definitional resources (ValueSet, CodeSystem, StructureDefinition, etc.) — adding them properly is a separate, codebase-wide effort, not a one-resource fix. - Verified, no code change needed: `SpreadsheetViewer.tsx` already receives its file via genuine chunked streaming (`BaseApi.downloadFile` → `streamRequest` → `readStreamedBody`, which reads `response.body.getReader()` in a loop and reports progress per chunk) — this was a direct question from the repo owner mid-planning; the answer is "already correct," not a task.

```ts
// Used for the SubscriptionStatus notificationEvent table's "time since previous" column.
// Rounds down to whole seconds and omits zero-valued larger units (e.g. "39s", not "0d 0h 0m 39s").
export const formatDurationBetween = (earlier?: TDateTime, later?: TDateTime): string | null => {
    if (!earlier || !later) {
        return null;
    }
    const earlierMs = new Date(String(earlier)).getTime();
    const laterMs = new Date(String(later)).getTime();
    if (isNaN(earlierMs) || isNaN(laterMs)) {
        return null;
    }
    const sign = laterMs < earlierMs ? '-' : '';
    const totalSeconds = Math.floor(Math.abs(laterMs - earlierMs) / 1000);
    const days = Math.floor(totalSeconds / 86400);
    const hours = Math.floor((totalSeconds % 86400) / 3600);
    const minutes = Math.floor((totalSeconds % 3600) / 60);
    const seconds = totalSeconds % 60;
    const parts: string[] = [];
    if (days) parts.push(`${days}d`);
    if (hours) parts.push(`${hours}h`);
    if (minutes) parts.push(`${minutes}m`);
    if (seconds || parts.length === 0) parts.push(`${seconds}s`);
    return `${sign}${parts.join(' ')}`;
};
```

```tsx
import {
    Box,
    Paper,
    Table,
    TableBody,
    TableCell,
    TableContainer,
    TableHead,
    TableRow,
    Typography,
} from '@mui/material';
import { TBaseResourceProps } from '../types/baseTypes';
import { TSubscriptionStatusNotificationEvent } from '../types/partials/SubscriptionStatusNotificationEvent';
import { formatDurationBetween, formatHumanDate } from '../utils/dateFormat';

type TSubscriptionStatusNotificationEventProps = TBaseResourceProps & {
    notificationEvent: TSubscriptionStatusNotificationEvent | TSubscriptionStatusNotificationEvent[] | undefined;
    // Always passed as an empty string by the generated SubscriptionStatus.tsx (via
    // partials_mapping_for_fields.py); unused here — see EncounterDiagnosis.tsx for precedent.
    field?: string;
};

const SubscriptionStatusNotificationEventPartial = ({
    notificationEvent,
    name,
}: TSubscriptionStatusNotificationEventProps) => {
    const entries = notificationEvent
        ? Array.isArray(notificationEvent)
            ? notificationEvent
            : [notificationEvent]
        : [];
    if (entries.length === 0) {
        return null;
    }

    // The array's wire order is not guaranteed to be chronological (the server's own example
    // payload isn't) — eventNumber is the authoritative row order for computing "time since
    // previous row".
    const sorted = [...entries].sort((a, b) => Number(a.eventNumber) - Number(b.eventNumber));

    return (
        <Box>
            <Typography variant="h6" color="text.secondary" sx={{ mb: 2 }}>
                {name}
            </Typography>
            <TableContainer component={Paper} variant="outlined">
                <Table>
                    <TableHead>
                        <TableRow>
                            <TableCell>Id</TableCell>
                            <TableCell>Timestamp</TableCell>
                            <TableCell>Time Since Previous</TableCell>
                        </TableRow>
                    </TableHead>
                    <TableBody>
                        {sorted.map((event, index) => {
                            const previous = index > 0 ? sorted[index - 1] : undefined;
                            const duration = previous
                                ? formatDurationBetween(previous.timestamp, event.timestamp)
                                : null;
                            return (
                                <TableRow key={`${index}`}>
                                    <TableCell>{String(event.id ?? '')}</TableCell>
                                    <TableCell>
                                        {formatHumanDate(event.timestamp) ?? String(event.timestamp ?? '')}
                                    </TableCell>
                                    <TableCell>{duration ?? '—'}</TableCell>
                                </TableRow>
                            );
                        })}
                    </TableBody>
                </Table>
            </TableContainer>
        </Box>
    );
};

export default SubscriptionStatusNotificationEventPartial;
```

### Task 5: Subscription (and SubscriptionStatus) → link back to Patient

**Design decision (confirmed with repo owner):** FHIR R4 `Subscription` has no `subject`/`patient` field, and this app's `TSubscription` type matches that. However, the repo owner confirmed the FHIR server supports `GET /4_0_0/Subscription?patient=Patient/person.<clientPersonId>` (and the same for `SubscriptionStatus`/`SubscriptionTopic`) — i.e. these resources *are* patient-searchable server-side, via the same `client_person_id` extension already visible in the example `SubscriptionStatus` payload (`{"id":"client_person_id","url":"https://icanbwell.com/codes/client_person_id","valueString":"..."}`). `src/partials/ReverseReference.tsx` already builds exactly this URL shape (`Patient/person.${id}`) when its *source* resource is a `Person` — but that only helps the *Person → Subscription* direction (Task 6). For the *Subscription instance → its own patient* direction, the value has to come from that instance's own `extension` array, since there's no reverse-reference config that can search "by extension value."

**Files:**
- Create: `src/partials/PatientReferenceFromExtension.tsx`
- Modify: `src/generator/template.javascript.component.jinja2`
- Regenerate: `src/pages/resources/Subscription.tsx`, `src/pages/resources/SubscriptionStatus.tsx`

**Interfaces:**
- Produces: default-exported `PatientReferenceFromExtension`, prop shape `{ extension: TExtension[] | undefined }`. Renders nothing if no `client_person_id` extension entry is found (safe no-op for any Subscription/SubscriptionStatus instance that doesn't carry it, rather than guessing wrong and showing a broken link).

- [ ] **Step 1: Create the partial**

Create `src/partials/PatientReferenceFromExtension.tsx`:

```tsx
import { Box, Typography } from '@mui/material';
import { Link } from 'react-router';
import OpenInNewIcon from '@mui/icons-material/OpenInNew';
import { TExtension } from '../types/partials/Extension';

type TPatientReferenceFromExtensionProps = {
    extension: TExtension[] | undefined;
};

// b.well-specific: Subscription and SubscriptionStatus resources carry the owning patient's
// client-scoped Person id as a top-level extension (id: 'client_person_id') rather than a
// structural subject/patient field — FHIR R4 Subscription has no such field. The
// `Patient/person.<id>` shape matches what ReverseReference.tsx already builds for
// Person-sourced ids, and was confirmed against a real Subscription search URL
// (`/4_0_0/Subscription?patient=Patient/person.<clientPersonId>`).
const CLIENT_PERSON_ID_EXTENSION_ID = 'client_person_id';

const PatientReferenceFromExtension = ({ extension }: TPatientReferenceFromExtensionProps) => {
    const clientPersonId = extension?.find((e) => e?.id === CLIENT_PERSON_ID_EXTENSION_ID)?.valueString;
    if (!clientPersonId) {
        return null;
    }
    const to = `/4_0_0/Patient/person.${clientPersonId}`;
    return (
        <Box sx={{ mb: 2 }}>
            <Typography variant="h6" color="text.secondary" sx={{ mb: 1 }}>
                Patient
            </Typography>
            <Link title="Direct link to Patient" to={to}>
                <Typography component="span">{to}</Typography>{' '}
                <OpenInNewIcon fontSize="inherit" />
            </Link>
        </Box>
    );
};

export default PatientReferenceFromExtension;
```

Note: this one is deliberately *not* added to `src/partials/index.tsx`/`Partials.X` — it's referenced with a plain relative import in the template edit below, since it isn't driven through the `partials_mapping`/`available_partial_resources` field-iteration mechanism (it needs to run once per resource, not once per matched field/type).

```ts
import type { ColDef } from 'ag-grid-community';
import { formatHumanDate, looksLikeIsoDate } from './dateFormat';

export interface SpreadsheetColumnsResult {
    columnDefs: ColDef[];
    rowData: Record<string, unknown>[];
}

const cellText = (value: unknown): string => (value === undefined || value === null ? '' : String(value));

export const buildSheetColumnsAndRows = (
    headers: unknown[],
    dataRows: unknown[][],
    hideEmptyColumns: boolean
): SpreadsheetColumnsResult => {
    // Decided once per column (not per cell) — a column can't sort numerically/chronologically
    // for some rows and lexicographically for others.
    const columnIsDate = headers.map((_, index) => {
        const cells = dataRows.map((row) => cellText(row[index])).filter((text) => text.trim() !== '');
        return cells.length > 0 && cells.every((text) => looksLikeIsoDate(text));
    });

    const columnDefs: ColDef[] = headers.map((header, index) => {
        const hasData = dataRows.some((row) => cellText(row[index]).trim() !== '');
        return {
            headerName: String(header),
            field: `col${index}`,
            editable: false,
            filter: true,
            floatingFilter: true,
            hide: hideEmptyColumns && !hasData,
            tooltipField: `col${index}`,
            sort: header === 'lastUpdated' ? 'desc' : undefined,
            ...(columnIsDate[index]
                ? {
                      cellDataType: 'date' as const,
                      valueFormatter: (params: { value?: Date | null }) =>
                          params.value ? formatHumanDate(params.value.toISOString()) ?? '' : '',
                  }
                : {}),
        };
    });

    const rowData = dataRows.map((row) =>
        row.reduce<Record<string, unknown>>((acc, cell, index) => {
            const field = `col${index}`;
            if (columnIsDate[index]) {
                const text = cellText(cell);
                acc[field] = text.trim() === '' ? null : new Date(text);
            } else {
                acc[field] = cellText(cell);
            }
            return acc;
        }, {})
    );

    return { columnDefs, rowData };
};
```
